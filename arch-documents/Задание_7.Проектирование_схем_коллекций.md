# Задание 7. Проектирование схем коллекций для шардирования данных

Онлайн-магазин «Мобильный мир» хранит информацию о заказах, товарах и
корзинах в MongoDB.\
Ниже описаны схемы коллекций, кандидаты на шард-ключи, выбранная
стратегия шардирования и обоснование выбора.

------------------------------------------------------------------------

## Коллекция `orders`

### Схема

``` js
orders: {
  _id: ObjectId,          // идентификатор заказа
  user_id: String,        // идентификатор клиента
  created_at: Date,       // дата/время оформления
  items: [ { product_id: String, price: Number } ],
  status: String,         // new/paid/shipped/...
  amount_total: Number,   // сумма
  geo_zone: String        // регион заказа
}
```

### Основные операции

- Создание заказа (интенсивная запись).
- Просмотр истории заказов конкретного пользователя.
- Получение статуса заказа по идентификатору.

### Шард-ключ и стратегия

- **Ключ:** `user_id` (hashed).
- **Стратегия:** шардирование по хэшу.
- **Обоснование:**
    - все заказы одного пользователя локализуются на одном шарде →
      быстрый доступ к истории;
    - равномерное распределение заказов по шардам;
    - отсутствие «горячих» диапазонов.

### Пример команды

``` js
use shop
sh.enableSharding("shop")
sh.shardCollection("shop.orders", { user_id: "hashed" })
```

## Коллекция `products`

### Схема

``` js
products: {
  _id: String,                 // SKU/артикул
  name: String,
  category: String,            // категория (electronics, books, ...)
  price: Number,
  stock_by_zone: [ { zone: String, stock: Number } ],
  attrs: { color, size, ... }  // произвольные атрибуты
}
```

### Основные операции

- Частые обновления остатков по SKU.
- Поиск товаров по категории и фильтрация по цене.
- Отображение карточки товара.

### Шард-ключ и стратегия

- **Ключ:** `category` (hashed).
- **Стратегия:** шардирование по хэшу.
- **Обоснование:**
    - листинги по категориям будут обращаться не ко всем шардам, а к
      подмножеству;
    - равномерное распределение категорий между шардами;
    - точечные операции по SKU всё равно работают быстро через `_id`.

*(Альтернатива --- `_id` (hashed), если упор на карточки товаров и
равномерность при большом числе SKU.)*

### Пример команды

``` js
use shop
sh.enableSharding("shop")
sh.shardCollection("shop.products", { category: "hashed" })
```

## Коллекция `carts`

### Схема

``` js
carts: {
  _id: ObjectId,
  user_id: String,            // для авторизованных; может быть null у гостя
  session_id: String,         // для гостя; у пользователя может быть null
  owner_key: String,          // нормализованный ключ: "user:<user_id>" или "sess:<session_id>"
  items: [ { product_id: String, quantity: Number } ],
  status: String,             // "active" | "ordered" | "abandoned"
  created_at: Date,
  updated_at: Date,
  expires_at: Date            // TTL
}
```

### Основные операции

- Создание корзины (гость или пользователь).
- Получение активной корзины по пользователю или сессии.
- Добавление/удаление товаров в корзине.
- Слияние гостевой корзины в пользовательскую.
- Автоматическое удаление старых корзин.

### Шард-ключ и стратегия

- **Ключ:** `owner_key` (hashed).
- **Стратегия:** шардирование по хэшу.
- **Обоснование:**
    - операции по корзине (чтение/обновление) таргетируются на один
      шард;
    - равномерное распределение по множеству пользователей и сессий;
    - простое слияние корзин при логине пользователя.

### Пример команды

``` js
use shop
sh.enableSharding("shop")
sh.shardCollection("shop.carts", { owner_key: "hashed" })
```

------------------------------------------------------------------------

## Итог

- **orders** → `user_id` (hashed): локализация истории пользователя,
  равномерная запись.\
- **products** → `category` (hashed): эффективные листинги по
  категориям при равномерном распределении.\
- **carts** → `owner_key` (hashed): быстрый таргетированный доступ к
  активной корзине и равномерность по пользователям/сессиям.
